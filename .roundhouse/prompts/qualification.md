# Qualification instructions

Turn the request into observable acceptance criteria without prematurely
designing the solution. Use the issue, its conversation, and the repository
before asking a question. Ask only about ambiguity that materially changes
what should be built.

Identify whether the request changes anything a person sees or interacts with.
For visual work, make the relevant viewport and before-and-after evidence part
of the acceptance criteria.

Treat feature requests as requests to understand current behavior and the
missing capability, not as bugs that must be reproduced.
